The [OpenSSF Baseline](https://baseline.openssf.org/versions/2026-02-19.html) records relationships between its controls and other public catalogs. Those links are orientation aids. A match does not mean the two texts are equivalent, or that progress on one automatically satisfies the other.

Raven’s existing [CI/CD Security Guide](/docs/) is organized around the NIST Secure Software Development Framework. This page lists the Baseline’s mapped catalogs in original language and points to the Raven routes that already, or now, sit next to them.

## Frameworks already used in Raven

- **SSDF (Secure Software Development Framework) 1.1** — Practice families for preparing the organization, protecting software, producing well-secured software, and responding to vulnerabilities. This is the spine of [Phase 1](/docs/phase-1/), [Phase 2](/docs/phase-2/), and [Phase 3](/docs/phase-3/).
- **NIST Cybersecurity Framework (CSF) 2.0** — Outcome-oriented functions for governing and reducing cybersecurity risk. The guide already cites CSF alongside SSDF on the [docs home](/docs/).
- **Cyber Resilience Act (CRA)** — EU rules for products with digital elements. See Raven’s [CRA page](/cyber-resilience-act/) and [Vulnerability Management](/openssf-baseline/vulnerability-management/).
- **P-SSCRM (Proactive Software Supply Chain Risk Management)** — A model for planning and comparing supply-chain risk programs. Raven’s project materials already treat it as a supporting reference.

## Other catalogs the Baseline maps

- **OpenSSF Best Practices Badge** — A voluntary self-assessment of FLOSS project practices.
- **SLSA (Supply-chain Levels for Software Artifacts)** — Integrity levels from source through build and distribution. Closest Raven home: [Build and Release](/openssf-baseline/build-and-release/) and [Phase 2](/docs/phase-2/).
- **ISO/IEC 18974** — Lightweight open-source security assurance, including how projects watch for known vulnerabilities.
- **OpenCRE** — A linking layer among security standards rather than a control set of its own.
- **OWASP SAMM** — A maturity model for software assurance across governance, design, implementation, verification, and operations.
- **PCI DSS 4** — Requirements for environments that store, process, or transmit cardholder data.
- **NIST SP 800-161** — Cybersecurity supply-chain risk management for systems and organizations.
- **UK NCSC Software Security Code of Practice** — Minimum expectations for commodity software producers.
- **DORA and NIS2** — EU operational-resilience and network-and-information-security rules that sit beside the CRA for some sectors.
- **CISA Secure by Design Pledge and Software Acquisition Guide** — U.S. guidance for producers and government buyers.
- **US Cyber Trust Mark** — A voluntary label program for consumer IoT.
- **MITRE ATT&CK** — Adversary tactics and techniques used to reason about threat coverage.
- **BSI TR-03185-2** — German guidance on a secure software lifecycle for open-source software.

## AI risk, which the Baseline catalog does not own

The Baseline’s external-framework list is oriented to software supply-chain and product-security catalogs. AI-assisted delivery still belongs in the same pipeline conversation. Raven covers that separately on the [NIST AI Risk Management Framework](/nist-ai-rmf/) page.
